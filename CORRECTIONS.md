# CORRECTIONS.md — retracted claims across all review rounds

*One dated row per retracted claim. Each row names the original
assertion, the artefact that falsified it, and the commit that
retracted it. This file is the audit trail; the numbered reports
themselves (01-08 + EXPERIMENTS_* in `documentation/`) read as final reports, with
no inline "prior drafts said X" narrative.*

---

## What lives here vs elsewhere

- **CORRECTIONS.md** (this file) — every retracted assertion,
  dated and traceable to a git commit + a source artefact
- **DEVIATIONS.md** — pre-registered *amendments* made before
  results existed (e.g., roster extension 6→8, WER-threshold
  refinement). Deviations are decisions the campaign then
  honoured. Corrections are claims the results then falsified.
  Different things.

## How to add to this file

When a claim in the reports is retracted:

1. Identify the artefact (JSON file, script line, or committed
   config) that falsified it — every entry should be reproducible
   from a `python -X utf8 -c` snippet
2. Add a row to the table above with round, original assertion,
   what retracted it, artefact, and commit SHA
3. **Delete the original assertion from the report.** Do NOT leave
   a "prior drafts said X" note in the report itself — the pattern
   of adding correction narrative next to a corrected number
   (documented as retraction #21 above) is exactly the thing this
   file exists to keep out of the reports. A paraphrase of the
   retracted claim in the report is not fine either.
4. **Verify with the line-wrap-safe check below.** A phrase-level
   `grep -rn` for a two-word retracted phrase misses hard-wrapped
   text (row 21 was three survivors of exactly that blind spot).
   The check has itself been evaded twice: once by hard-wrap (row 21),
   once by narrow scope + narrow regex (round 8 added six inline
   retraction paragraphs across 08 and EXPERIMENTS that this check
   was written to catch and didn't, because its glob was
   `0[1-7]*.md` and its regex was `(prior|earlier)\s+drafts?` —
   missing 08, missing EXPERIMENTS, and missing the phrasings
   "earlier revisions" / "prior versions" / "previously
   reported / stated / said / carried"). The check below covers
   both misses:

   ```bash
       r'(?i)retracted\s+(?!(as|as\s+CORRECTIONS|;\s*see|claim|phrase|row))',
       r'(?i)round[-\s][3-9]',
       # Multi-round review-bookkeeping ranges (R7-R23, R11-R18, etc.).
       # Starts at R7 to avoid firing on R1-R10 (a legitimate reference
       # to the Phase B external red-team review, pre-project) and on
       # R2/R3 (campaign labels, not review-round labels). Added R24
       # after the header meta-line in docs/index.html was caught
       # naming "R7-R23 review-round backlog" — reader-facing text
       # should say "revised through <date>", not enumerate rounds.
       r'\bR([7-9]|[1-2][0-9])\s*[-–]\s*R[0-9]+\b',
       r'(?i)after[-\s]review',
   ]
   # NOTE: earlier revisions of this check also targeted r'CORRECTIONS\.md'
   # and r'F-1[2-9]'. Both were dropped because they fired on every
   # sanctioned pointer that rule 3 mandates (Prior X retracted; see
   # [CORRECTIONS row N]) and on every legitimate reference to F-12
   # (which is now a published finding). A check that always reports
   # legitimate hits trains you to skim past hits — which is how the
   # round-8 narratives got through. The `retracted\s+(?!...)`
   # lookahead already does the discriminating work.
   # Cover all live docs, not just 01-07: 08, EXPERIMENTS_*, plus
   # top-level README + DISCLAIMER + docs/index.html.
   paths = (
       sorted(glob.glob('documentation/0[1-8]*.md')) +
       sorted(glob.glob('documentation/EXPERIMENTS_*.md')) +
       ['README.md', 'DISCLAIMER.md', 'docs/index.html'] +
       sorted(glob.glob('analysis/round*-vs-round*-comparison.md'))
   )
   for f in paths:
       try:
           text = open(f, encoding='utf-8').read()
       except FileNotFoundError:
           continue
       for pat in targets:
           for m in re.finditer(pat, text):
               line = text[:m.start()].count(chr(10)) + 1
               snippet = re.sub(r'\s+', ' ',
                                text[max(0,m.start()-30):m.end()+80])
               print(f'{f}:{line}  [{pat}]  ...{snippet}...')
   "
   ```

   Each hit is either (a) an inline retraction narrative to
   collapse to a one-sentence pointer per rule 3, or (b) a
   legitimate use inside a `Prior X retracted; see [CORRECTIONS
   row N]` sentence that the regex whitelist above lets through.
   The `retracted` regex uses a negative-lookahead for the
   one-line-pointer form so legitimate pointers do not fire.
   Add new retraction-narrative phrasings to the `targets` list
   as they surface — every phrasing the check missed once is a
   phrasing it should catch next time.
5. **Run this check before commit, not after review.** Rounds 8
   and 9 each added ~8 new corrections; the cadence was not
   converging because rule 4's check was running post-mortem
   (after a reviewer pointed at hits) rather than pre-commit
   (as a gate that refuses to accept new inline narratives). With
   the check now producing zero hits on a clean tree, "zero hits"
   is a meaningful requirement — put the block above into a
   `pre-commit` hook or a habit of running it before every
   `git commit`, and any new inline retraction narrative fails
   the gate before it ships.
